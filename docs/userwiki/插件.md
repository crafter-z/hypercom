# 插件使用

HyperCom 插件是由用户安装的第三方代码。应用提供可选的轻量插件市场源，也支持本地目录或 ZIP 安装；市场源只是远程元数据和下载地址，不代表官方安全审查或代码签名。安装前请确认来源、代码和权限用途。权限列表是插件声明与宿主支持能力的交集，不是绝对沙箱保证。

本页说明普通用户的安装、授权、使用、升级和故障处理。编写插件请看[插件开发指南](../plugin-development.md)。

## 安装前要知道

- 插件代码会被复制到应用配置目录旁的 `plugins/<插件 ID>/`。直接修改源目录不会修改已安装副本。
- 多数插件在主窗口的 Worker 中运行；独立弹出窗口不运行插件。插件隔离视图当前只有 Windows 原生承载，macOS/Linux 会明确拒绝创建隔离视图，不会偷偷降级成主窗口网页。
- 插件可能访问串口数据、发送串口数据、访问网络、读写插件私有数据、读取或修改你选择的文件/文件夹，或使用剪贴板。只授予你理解用途的权限。
- 打开插件视图不会自动连接或断开串口，也不会自动向设备发送数据。
- 有些插件只有网页视图、没有后台 Worker；安装、启用和网页信任的流程与普通插件相同。

## 插件市场

插件设置页的市场区域可以从一个静态索引源发现插件。新配置默认使用 HyperCom 官方源；用户可以替换为自己的源。市场源只保存插件描述 JSON 的链接；应用会再读取每份描述中的 manifest、版本、权限和 ZIP 下载地址。

1. 打开「设置 → 插件」，在「插件市场」中填写市场源地址。
2. 点击「同步市场」。这一步会使用当前输入地址检查索引和插件描述，并在成功后立即保存市场源，不需要再点击底部普通设置的「保存全部」。
3. 在市场列表中查看插件名称、ID、版本、状态和权限数量。`未安装` 显示「安装」，有更高版本显示「更新」，已是当前版本则显示「已是最新」。
4. 点击安装或更新后，仍需经过现有的权限和可信网页确认；市场不会自动启用插件，也不会自动恢复旧授权。

应用自动检查软件更新时也会检查插件市场更新（周期相同、分别记账）。发现已安装插件有可用更新时，通知中心会显示一条粘性提示，右下角也会出现同样的提示；点击提示可直接打开「设置 → 插件」。提示只告知可用更新，不会自动下载或安装插件。

市场检查失败不会安装或替换现有插件。切换市场源会清除旧的市场结果，已安装插件不会因为从索引中移除而自动卸载。市场安装会保留插件 `data/`，但生成新的 `installGeneration` 并清除普通授权与网页信任。

官方示例市场源见 [`crafter-z/hypercom-plugin-marketplace`](https://github.com/crafter-z/hypercom-plugin-marketplace)。索引和描述的完整 JSON 格式、发布规则和本地演示见[插件开发指南的市场章节](../plugin-development.md#插件市场发布与更新)以及仓库中的[本地静态市场示例](../../examples/plugin-marketplace/README.md)。

## 安装、授权和启用

![插件设置页](images/settings-plugins.png)

1. 打开「设置 → 插件」；点击「安装目录…」选择包含 `manifest.json` 的插件目录，或点击「安装 ZIP…」选择插件归档。
2. 安装完成后按用途分组审阅权限（观察设备数据、向设备发送或改变连接、读取/保存/导出文件、访问网络/系统程序/剪贴板、应用内显示与设置）。默认只选实际安装包声明且宿主支持的普通能力；高风险 `shell:execute` 默认不选，必须由你明确勾选。若插件包含可信网页视图，还要单独勾选网页信任；混合包未获信任时会保持禁用。市场预览与实际安装包不一致时，确认框会列出差异。
3. 点击「按此选择启用」应用选择；点击「稍后处理」会保留插件但不运行，之后可在插件设置中再次「审阅权限」。取消勾选并保存会撤销对应能力。
4. 插件安装、卸载、启用 / 禁用和权限变更会立即保存，不受设置窗口底部「取消」影响。
5. 安装后点击「刷新」可重新读取插件状态。插件按钮、端口右键菜单、插件输出面板和视图入口是否存在，取决于插件自己的 manifest 声明。

常见权限含义：

| 权限 | 用途和注意事项 |
| --- | --- |
| `ui:view` | 创建插件隔离视图、表格或工具页。 |
| `rx:bytes` | 读取原始 RX 字节；适合表格、波形和 TTY 等字节协议。 |
| `terminal:read` | 读取 TRX 终端行；TTY 没有相同的行语义。 |
| `terminal:write` | 在已打开的 TRX 终端中写入插件旁注，不会把内容发送给设备。 |
| `ui:tabs` | 让插件 Worker 打开、激活、关闭和管理自己的工作区标签。 |
| `serial:control` | 打开和关闭串口，可能中断现有设备会话；受插件声明的端口白名单限制，不包含发送权限。属于敏感权限，授权时会单独提示。 |
| `serial:send` | 向已连接串口发送数据；还受插件声明的端口白名单限制，不包含打开/关闭权限。分块 `serial.sendBytes` / `serial.sendFile` 会固定端口和连接代次，取消或拔插不会自动重发。属于敏感权限，启用前会单独提示。 |
| `http:request` | 通过宿主发起网络请求，默认继承系统代理；插件可自行声明 URL 白名单收紧范围。属于敏感权限，启用前会单独提示。 |
| `shell:open` | 用系统默认程序打开 http、https 或 mailto 链接；不会执行本机命令。属于敏感权限，启用前会单独提示。 |
| `shell:execute` | **高风险**：按操作系统语义运行本机程序并返回退出码和 stdout/stderr；也可显式启动 `shell.start`，分别消费 stdout/stderr 并取消单个任务。程序可能读写本机数据、访问网络或运行其他程序。属于敏感权限，启用前会显示一次风险说明。 |
| `fs:assets` | 读取插件自带的代码与资源文件，不能修改。 |
| `fs:storage` | 读写插件自己的 `data/` 私有文件；不等于访问应用配置或任意文件。 |
| `fs:open` | 通过系统文件选择器读取你选定的外部文件；开发者可用 `fs.openFile` 取得只读句柄并按窗口读取，但不会获得目录授权。 |
| `fs:open-dir` | 通过系统目录选择器只读访问你选定的文件夹：列出目录、读取文件和元数据。与 `fs:open` 分开授权。 |
| `fs:export-dir` | **目录导出的推荐最小权限**：只在你通过系统目录选择器选定的白名单文件夹内创建/覆盖导出文件，并按需建立父目录；不能读取、删除、重命名或追加，也不能访问未选中的目录。属于敏感权限。 |
| `fs:save` | **每次另存为的最小权限**：每次都弹出系统 Save As，由你选择任意位置并确认覆盖；插件不能自行指定绝对目标路径，也不会获得后续目录访问权。开发者可用 `fs.createFile` 分块写入后显式 commit。属于敏感权限。 |
| `fs:write-dir` | **兼容保留的高风险权限**：在你选定的文件夹内创建/覆盖/追加文件、建目录、删除和重命名。仅导出时优先授予 `fs:export-dir`，只有需要删除/重命名等完整修改能力时才授予此权限。属于敏感权限，授权时会单独提示。 |
| `storage` | 读写插件自己的 JSON 键值数据。 |
| `clipboard` | 读写剪贴板文本，并允许插件页面接收粘贴；可能接触你复制到剪贴板的其他内容。 |
| `notify` | 在应用内弹出插件通知；有频率和长度限制，超出会被丢弃。 |

### shell.execute 授权

安装或启用时，`shell:execute` 只需一次敏感权限确认，不会在插件每次运行命令时重复弹窗。插件可按操作系统语义传入 `program`、`args`、`cwd`、继承环境上叠加的 `env`、可选 UTF-8 `stdin` 和调用方选择的 `timeoutMs`；支持相对或绝对路径，也可显式选择 `cmd.exe`、PowerShell、`sh` 等解释器。禁用、撤权、显式重载、卸载或替换会取消并等待直接子进程；仅 Worker 崩溃或停止时可能只丢弃回执，不保证取消已启动的命令，它可能运行至自身结束、调用方 timeout 或后续用户禁用。不能承诺终止进程树或撤销已经发生的副作用。用户是执行本机程序的第一安全责任人，应在授权前审阅插件来源、代码和参数。

`shell.execute` 不额外设置命令专用并发、输出或参数业务配额；`timeoutMs` 缺省或为 `0` 表示不设截止，正整数为调用方选择的毫秒值。实际仍受操作系统、进程、可用内存及宿主通用 RPC 在途限制。

需要实时看到输出的插件可在同一 `shell:execute` 授权下使用 `shell.start`。插件必须并行消费 stdout/stderr，或在启动时把不需要的一侧设为 `discard`；两条管道各自保持顺序，不保证跨管道的全局时序。取消只作用于该任务的直接子进程，`release` 只释放任务记录；不会承诺终止进程树或撤销已经发生的副作用。旧 `shell.execute` 继续保留。

插件读写自己的私有数据（KV 和 `data/` 文件）、读写你选择的目录、发起网络请求时，应用不设统一的大小或数量上限：保存多少数据、写多大文件、请求多久、响应多大由插件自己决定，实际占用受磁盘空间和网络条件限制。长期使用的插件可能占用较多磁盘或流量；卸载会删除其私有数据。`fs:open-dir` / `fs:export-dir` / `fs:write-dir` 的目录授权只存在本次应用运行期间，重启后需要重新选择目录；`fs:save` 不保留目录授权，每次都要重新选择保存位置。三种保存权限不互相隐含，撤销后旧插件 API 引用同样不能继续使用；已完成的设备/文件副作用不能通过撤权回滚。

## 可信网页

部分插件会声明“可信网页”，用于 AI 助手、日志分析和报告页面。安装或首次启用时，权限审阅中会有独立的网页信任勾选项；普通权限选择不能替代它。未勾选时混合包保持禁用；从设置单独管理网页信任也必须明确确认。插件卡片上会显示「网页需要独立信任」或「已信任网页」。

- 信任后，网页可以连接互联网、本机和局域网服务，读取你选择的文件、使用剪贴板、导出下载并持久保存网页数据。它也可能把日志或剪贴板内容上传网络，请只信任可靠来源。
- 网页网络仍遵守浏览器跨域和证书规则；Worker 的「插件代理」设置不影响网页。模型服务连接失败时核对服务 CORS 或本地桥接配置。
- 插件的 Worker 网络默认继承系统代理；在「设置 → 插件 → 插件代理」中启用并填写地址后改用该代理。请求的时长和响应大小由插件决定，应用不设统一上限。代理凭据明文保存在 `config.json`，请只在可信环境填写。
- 网页内可在插件自带的本地页面之间跳转或刷新；你点击外部 HTTP(S) 链接时会用系统浏览器打开，不会在应用内新开窗口。
- 同一安装版本重启不重复确认；升级或替换安装会更换 `installGeneration`，不复用旧代次的网页数据，且必须重新确认信任。
- 「撤销网页信任并禁用」立即停止页面，保留数据。「清除网页数据」会先禁用插件，再清除 Cookie、登录状态、localStorage 和 IndexedDB；不会删除插件普通 `data/`。操作不可撤销，完成后插件保持禁用。
- 卸载也清除网页数据。应用配置导出不包含这些数据，导入不能恢复已撤销的网页信任。
- 当前仅 Windows 支持原生插件网页；可信网页也不能直接运行主窗口 Tauri 命令或任意本机程序。

## 插件入口和串口关系

插件可能提供以下入口：

- **插件输出**：插件产生输出后才会在主窗口底部出现；面板可以折叠。
- **串口内容视图**：在串口内容区上方的「显示方式」中选择插件视图。它会替换当前标签的原始终端显示，但不改变串口连接和参数。
- **独立工作区标签**：在标签栏右侧「+」中选择插件工具或视图。绑定端口的标签固定绑定打开它时的端口，不会因之后切换活动串口而重绑。
- **侧边栏按钮 / 端口右键菜单**：由插件自行声明，具体文案和行为以插件说明为准。

注意：

- 需要 `terminal:read` 的插件依赖 TRX 行数据。端口切换到 TTY 后，插件仍可能有字节输入，但不会收到同样的行回调。
- 需要 `rx:bytes` 的插件可以处理原始字节；它仍然只能从打开视图之后开始收到数据，不补发历史数据。
- 插件视图和独立插件标签不支持弹出窗口。需要弹出终端时，先切回「原始终端」；TTY 也不支持弹出。
- 关闭插件标签只关闭该插件会话，不关闭原始终端、同端口其他视图或物理串口。要停止连接，请单独断开串口。
- 选择视图、恢复工作区标签和打开工具页都不会自动连接串口。
- 页面交互分为两类：连续预览会合并为当前文档的最新值；保存、发送等离散动作通过一次性状态反馈报告 `accepted`、`busy`、`unavailable` 或 `unknown`。`accepted` 只表示已进入插件 Worker，不代表设备或业务动作完成；`unknown` 时重试前请核实是否已执行。
- 旧页面的 `view.send` 仍兼容，但拥塞或未获确认会显示节流提示，不会返回可等待的拒绝 Promise。无 Worker 的可信网页只能显示页面，不能通过这些接口调用 Worker。

## Sensor Workspace 示例

仓库中的 [Sensor Workspace 示例](../../examples/plugin-views-demo/README.md) 提供 Sensor table、Sensor waveform 和 Sensor settings 三个原生视图。

### 安装和权限

在「设置 → 插件 → 安装目录…」选择 `examples/plugin-views-demo`，安装后授予示例所需的 `ui:view`、`rx:bytes`、`ui:tabs` 和 `storage` 权限。

如果之前安装的是旧版本，重新选择当前示例目录会升级到当前版本 1.0.2。不要先卸载：升级会保留插件私有数据；卸载会删除私有数据。

### 打开 Sensor settings

- 标签栏右侧「+」选择 **Sensor settings**，无需先打开串口。
- 也可以点击插件侧边栏的 **Sensor settings**。
- 两个入口会复用同一个已打开的设置页，不应创建两个独立 Settings 页面。
- Settings 页不绑定串口，不会借用最近使用的串口，也不会发送设备命令。

### 打开 Sensor table

1. 先打开或激活具体的 COM 串口标签。
2. 点击该标签右上角「+」。
3. 选择 **Sensor table**。

表格标签会绑定当前 COM 口；串口即使尚未连接，表格也可以打开，但不会自动连接。若「+」中没有 Sensor table，请检查：当前是否为普通 COM 标签、插件是否启用、是否授予 `ui:view` 与 `rx:bytes`，以及插件视图是否支持当前端口模式。

### Sensor Workspace 的重复打开规则

同一插件、安装代次、视图、绑定端口和实例会复用已有标签。重复点击 Settings 或同一端口的 Table 入口应聚焦原页面，而不是无限创建副本。Worker 明确使用不同实例的插件可以创建多个独立会话。

## 升级、禁用、卸载和数据

### 升级

- 同一插件 ID 通常只有版本号严格更高时才允许覆盖安装；再次选择相同或更低版本时会先弹出替换确认，确认后才替换代码，取消则保留原安装。
- 升级/替换会替换插件代码和资源，保留插件 `data/`；网页数据按 `installGeneration` 隔离，不复用旧安装代次。
- 升级/替换会生成新的安装身份并清除普通授权与网页信任；安装后必须重新审阅并授权。
- 「重载已安装代码」只重启当前安装的代码副本，不重新读取来源目录，也不改变安装身份、权限、网页信任或数据；适合插件自身状态卡住时使用。该按钮仅在插件已启用且 manifest 无错误时可用，成功后提示「插件代码已重载；视图将独立重新加载」。
- 升级或重载期间旧插件标签可能显示不可用占位；重载或重新打开视图后会重新加载。

### 源码修改不会自动生效

如果你从源码目录安装了插件，修改 `main.js`、`manifest.json` 或 UI 文件后不会热更新已安装副本。请递增 manifest 中的版本号，再通过「安装目录…」覆盖安装。

`npm run tauri dev` 只热更新 HyperCom 宿主源码和 Rust 开发程序，不会同步 AppData 中已安装的插件副本；「刷新」也不会重新复制插件代码。

### 禁用和卸载

- **禁用**：停止插件运行，但保留已安装代码和私有数据。
- **卸载**：删除插件代码、授权、私有数据及网页站点数据。卸载期间会显示当前阶段和已用时间；关闭视图、清理网页数据或删除文件可能需要等待。需要保留阈值、历史或其他插件数据时，不要先卸载。
- 应用配置导出不包含插件代码和插件私有数据。备份中的插件授权只有在安装身份仍一致时才可恢复；同 ID 的升级、重装或换代码不能自动恢复授权。

## 故障处理

| 现象 | 先检查 |
| --- | --- |
| 插件不显示 | 是否安装成功、启用、刷新状态；权限是否已授予；插件是否只声明了其他入口。 |
| 插件状态卡住，想重新启动代码 | 点「重载已安装代码」；它只重启已安装副本，不重新读取来源目录。改过源码仍需递增版本号后覆盖安装。 |
| 修改源码后没有变化 | 你运行的是已安装副本；递增版本号并重新覆盖安装。不要先卸载，以免删除私有数据。 |
| 视图显示不可用 | 先看页面给出的失败原因。插件缺失、禁用、权限/信任不足、端口绑定或模式不匹配等结构性问题，点击「插件设置」修复后会重新评估；Worker 停止、初始化超时或运行时故障等瞬时问题可点击「重试视图」。也可关闭占位标签。 |
| 没有 Sensor table | 激活普通 COM 标签后再点右上角「+」；确认 `ui:view`、`rx:bytes` 已授权，当前插件不是旧安装副本。 |
| 收不到插件数据 | 核对绑定端口、TRX/TTY 模式、`terminal:read` / `rx:bytes` 权限；插件从打开后的新数据开始接收，不回放历史。 |
| 插件反复崩溃或自动禁用 | 点击「刷新」，查看插件错误和「关于 → 诊断日志」；检查初始化 Promise、权限和资源声明。 |
| 设置窗口「取消」没有撤销插件操作 | 插件安装、卸载、启用 / 禁用和授权是立即持久化操作；底部「取消」只影响普通设置和代理设置。 |

不要手动删除 `plugins/`、`data/` 或事务文件来“修复”插件；这样可能破坏升级恢复并丢失私有数据。遇到持续错误时，保留插件来源、版本、安装身份和操作步骤，导出「关于 → 诊断日志」后再反馈问题。
