# HyperCom v0.1 交付路线图

> 生成日期: 2026-07-20 · 依据: `GAPS.md` 全文 + `plans/01-09` + 源码抽查 · 目标: 从高质量 demo 推进到可交付 v0.1

---

## 总方针

1. **先做"不可缺少可见性"，再做"新功能"。** Phase A 全部是把"已有功能但用户看不到/操作不动"补齐。
2. **后端在前、UI 在后、分发最后。** 引脚轮询、panic hook、updater 都需先在后端落地。
3. **真机测试不是开发任务，是交付验证关卡。** 须有硬件矩阵文档 + 至少 2 种主流芯片实跑。

## 调整 GAPS 原建议顺序的理由

1. **错误提示提到 Phase A 最前**：它是其他 phase 失败回路的依赖（重连失败要 toast、引脚失败要 toast）。先做真机会缺反馈。
2. **真机测试后置到 Phase E**：必须先有自动重连 + 引脚提示 + panic hook，真机测试才有意义——否则光测一堆崩溃 bug 还没手段恢复。
3. **崩溃恢复提前到 Phase B**：跟自动重连同源，都是把"故障可恢复"做扎实。
4. **i18n 收尾挪到 Phase F**：技术债最低、不影响功能；新功能都接完了一次性翻译不会漏。

- `npx tsc --noEmit` 0 errors

- 无新增 `as any` / `@ts-ignore`
- 涉及 UI 改动的 Phase A/C/D 须做手工测试清单相应项验证

v0.1 发版前 4 项必须全绿 + Phase A/B/C/D/E 全部完成。
